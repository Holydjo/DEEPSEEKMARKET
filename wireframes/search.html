1Result summary is specific

“38 providers near Le Plateau” names the place and count; the subline repeats the category, radius and sort. Active filters appear as removable chips so the state is always visible and explainable.

2Progressive filters

The desktop rail exposes the six filters that matter for local services. On mobile they live in a bottom sheet with a sticky “Show 38 results” action. Every filter change updates the URL and the count before applying.

3Card hierarchy

Name + verified → category/location → rating/distance/response → service settings → price. The accent “Request” is secondary to opening the profile, but supports a fast path for decisive customers.

4Distance honesty

Distance is computed from the resolved search origin. If the customer only chose a city, cards show neighbourhoods and no distance. Maps never reveal a provider's exact home address — only an approximate area circle.

5Map is optional at 1180 px

Below 1100 px the map becomes a toggle above results. On mobile it is a 130 px preview that expands to full screen. The list never shrinks below 60% of the width on desktop.

6Empty state is a route, not a wall

Show: “No braiders within 5 km of Le Plateau.” Actions: extend to 10 km, clear the travel filter, browse Rosemont, or request a provider. Never show unrelated paid results as if they matched.

7Pagination and performance

12 results per page with “Load more” (no numbered pagination on mobile). Skeleton cards match final dimensions. Search state is fully in the URL so back/forward and sharing work; map pins are server-derived and stable.

8Accessibility

Filters are real checkboxes with labels and counts. Sort is a labelled select. Map has a text alternative (“5 results on map, list below”). Pin numbers match visible card indices. Focus moves to results heading after applying filters.

02BMobile

Search stays at the top; the map is a glance, not a destination. The filter sheet is the only modal, and it previews the result count before applying.

9One-handed search

Query, location, filters and sort are all in the top third. Result cards keep the action small and the whole card tappable; the primary “Request” lives on the profile, not in the dense list.

10Filters preview the outcome

The sheet shows “Show 38 results” and a live match count. It is dismissible by drag or backdrop; applied filters persist in the URL. The sheet never covers the entire screen — context stays visible above.

11Map preview is a teaser

130 px is enough to communicate “there are providers around you”. Tapping opens a full-screen map with a bottom card carousel. On desktop the map is persistent; on mobile it is intentional.

12Empty state offers next steps

Extend radius, remove a filter, browse a nearby neighbourhood, or request a provider. The request form captures the unmet need as a lead for supply acquisition — clearly labelled, never disguised as a result.
